Network Auto-configuration: DHCP and APIPA

How a machine gets an IP address automatically — and what happens when the server that hands them out is unreachable.

The win

By the end of this lesson you'll know that when a Windows DHCP client can't reach a DHCP server, APIPA steps in automatically — the exact distinction you missed (Q22).

Two automatic processes

ProcessWhen it runsWhat it does
DHCPNormal startupServer assigns IP address, subnet mask, gateway, DNS
APIPADHCP server is unreachableClient self-assigns a link-local 169.254.x.x address

DHCP (Dynamic Host Configuration Protocol) is the normal way a device gets its network settings. The client asks the network for a DHCP server, and the server leases it an IP address plus configuration.

APIPA (Automatic Private IP Addressing) is the fallback. If the Windows client cannot reach a DHCP server, it automatically assigns itself a link-local address in the 169.254.0.0/16 range. This lets the machine talk to others on the same local segment, but it has no internet access.

The trap

The question's tell is "unable to reach a DHCP server." That's APIPA. Static IP is manual, a DHCP relay forwards requests to a server on another network (still needs the server), and RAS is remote access — none of them is the automatic fallback.
