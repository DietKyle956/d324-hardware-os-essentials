Storage Management: NVM Scheduling & the File System Interface

Two layers of the storage stack that get tested with look-alike questions. Learn which one allocates memory and which one gives you files.

The win

The storage stack

NVM scheduling

NVM stands for non-volatile memory — storage that keeps its data when power is removed (the SSD flash from Lesson 2).

NVM scheduling is the job of deciding where data gets written on that non-volatile memory. An IT professional uses it to manage the allocation of nonvolatile memory — placing and re-arranging data across the device's blocks.

Because flash cells wear out after a finite number of writes (Lesson 2's trap), the scheduler spreads writes out evenly — a side benefit is better performance and longer device life, but the core purpose is allocation, not speed.

The file system interface

The file system organizes raw storage into the files and folders you actually use. Its interface is the set of operations it hands to the OS — create, open, read, write, delete, rename.

The primary function of the file system interface is to allow the system to access and manage files. Permissions and ownership are real, but they sit on top of that primary job — they're not the point of the interface itself.
