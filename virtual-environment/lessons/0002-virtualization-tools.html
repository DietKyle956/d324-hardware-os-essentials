Virtualization Tools

Four ways to use virtual machines. Know which tool isolates throwaway testing and which crosses hardware boundaries.

The win

By the end of this lesson you'll know a virtual sandbox is for testing that never touches the physical machine, and cross-platform virtualization runs software built for one type of hardware on another.

The four tools

ToolWhat it doesExam tell
Virtual sandboxIsolated, disposable environment to safely run/test untrusted code"files not saved… never affect the physical machine"
Test developmentBuild and test software in VMs with snapshots and rollbacks"developing/testing, snapshots"
Application virtualizationRun an app without installing it locally; isolated from the OS"run an app without local install"
Cross-platform virtualizationRun software built for one OS/hardware on a different one"designed for one hardware… runs on different hardware"

A virtual sandbox is a safe, isolated box. You test an application inside it, and because changes aren't written to the physical machine's drive or memory, the host stays untouched. If the app is malicious or misbehaves, nothing spills out.

Cross-platform virtualization lets an application written for one type of hardware (or OS) run on a different one — for example, a Windows program running on a Mac, or software built for one CPU architecture running on another.

The trap

Sandbox and cross-platform both involve isolation, but for different reasons. The sandbox isolates to protect the host (throwaway, nothing saved). Cross-platform isolates to bridge incompatible hardware/OS. Read the question's goal, not just the word "virtual."
