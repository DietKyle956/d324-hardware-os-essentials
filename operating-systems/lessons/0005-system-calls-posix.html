System Calls and the POSIX API

Programs talk to the kernel through system calls. POSIX standardizes those calls with short, generic names — and that's exactly how you tell them apart from Windows.

The win

By the end of this lesson you'll know Read() is the POSIX-style call, while CreateProcess(), CreateFile(), and TerminateProcess() are Windows API style — the exact distinction you missed (Q5).

What a system call is

A system call is the programmatic interface between applications and the operating system's kernel. When a program needs the OS to do something privileged — read a file, start a process, allocate memory — it requests it via a system call. The program says "OS, please do this," and the kernel carries it out.

POSIX vs the Windows API

POSIX (Portable Operating System Interface) is a standard API that lets programs work the same way across UNIX-like systems — UNIX, Linux, and macOS. It uses short, generic, lowercase names: read(), write(), open(), close(), fork(), exec().

The Windows API (Win32) uses a different naming style — longer, capitalized, "action + noun" names like CreateProcess(), CreateFile(), and TerminateProcess().

The trap

The exam asks for a system call used by the POSIX API. That's Read() — short and generic. The other three options are Windows API calls, recognizable by Create… and Terminate… prefixes. When you see UNIX/Linux/macOS, think short names.
