Operating Systems · Lesson 1

Where the OS Lives at Runtime

Opening the Operating Systems unit. Four components — CPU, RAM, GPU, SSD — and one clear division of labor.

The win

By the end of this lesson you'll know exactly which component holds the OS's system code and running programs (RAM), which executes them (CPU), and why it isn't the SSD.

The runtime pipeline

When you power on, the operating system is copied from long-term storage into RAM. RAM is the working memory — it holds the OS's system code and every running program while they execute.

Four components, four jobs

ComponentJobAnalogy
CPUExecutes instructionsThe worker
RAMHolds running code and dataThe workbench
GPURenders graphics (specialized math)The illustrator
SSDLong-term, non-volatile storageThe filing cabinet

Why RAM, not the SSD?

RAM is far faster than the SSD — fast enough to keep up with the CPU. But RAM is volatile (it forgets on power-off), so the permanent copy stays on the SSD and is loaded into RAM each boot. Speed is why code runs from RAM, not from storage.
