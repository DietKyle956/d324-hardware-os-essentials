Kernel Building Blocks: Process Control Management

An operating system is built from a small set of subsystems. This lesson nails the one that tracks every process — and separates it from the two blocks that sound like it.

The win By the end of this lesson you'll know which kernel building block keeps track of each process and whether it should run or wait — the exact distinction you missed on the pre-assessment (Q3).

A process is a running program

A process is a program that is loaded into memory and executing. A modern OS juggles dozens at once — your browser, your text editor, background services — each needing CPU time, memory, and I/O. The part of the OS that manages all of this is the kernel, and the kernel is organized into building blocks (subsystems), one per resource.

The trap Three of these sound alike. The exam's tell is "keeps track of each process … whether to run it or wait for some event." That is process control management — not memory management (RAM), and not scheduling (which picks the next one). Track-the-process's-state = process control.

Process control management, up close

For every process, the OS keeps a record — often called the process table or process control block (PCB) — storing what the process is doing and, critically, its state. Process control management writes and reads that state so it always knows whether a process should be running now or waiting for some event (like a disk read or a keystroke).

Ready means the process wants the CPU but isn't on it yet. Running means it currently has the CPU. Waiting (also called blocked) means it's paused until some event finishes. Tracking and updating these states — "run this one now, wait on that one" — is the job of process control management.

How it differs from scheduling and memory

  • Scheduling and dispatch does the choosing: it looks at the ready processes and decides which one gets the CPU next, then hands it over. It doesn't track the "waiting for an event" state.
  • Memory management handles RAM — allocating and freeing space for processes. It tracks memory, not processes.
  • Process control management tracks each process and its state (run or wait) across the whole life of the process.
